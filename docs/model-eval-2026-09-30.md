# 모델 평가 2026-09-30

최신 모델 후보를 지금 쓰는 모델과 같은 과제로 나란히 잰 기록이다.
평가 도구는 `src/eval/models-eval.ts`(`npm run eval:models`). 과제 원문과 사례 자료는
공개 저장소에 두지 않고, 여기에는 집계만 남긴다.

## 결론

1. **등록부는 바꾸지 않는다.** 판정에서 최신 모델이 더 낫다는 근거가 없고,
   위험을 «낮게 부르는» 쪽은 오히려 최신 모델이 더 잦았다.
2. **첫 작성 비교는 무효였다.** 현행 구성의 초안이 출력 한도에서 문장 중간에 잘렸고, 후보는
   생각 예산이 더해져 끝까지 썼다. 같은 한도로 다시 쟀다(아래 «작성 재측정»).
   관리자 Opus 5.5 는 4.8 보다 확실히 낫다(45 대 3, 두 심사 모두). 단일 모델은 두 심사의 판정이
   갈려 앙상블을 그대로 둔다. 한 급 위 3사(C)는 두 심사 모두 이겼지만 건당 +38% 다(오너 결정).
4. **운영 작성 도우미의 3사 초안은 3분의 2 이상이 한도에서 잘린다**(아래 «운영 한도 점검»).
   고치는 규칙 두 가지를 재 봤지만 둘 다 득보다 실이 커서 켜지 않았다.
3. **구성 C 는 무효다.** 평가 도중 Anthropic 잔액이 바닥나 105건 중 78건이 오류였다.

## 판정: 변경 위험 등급 105건 (오너 확정 라벨)

라벨 분포: 높음 55 · 중간 19 · 낮음 31. «낮게 부름» 은 정답보다 낮은 등급으로 답한 건수다.
규제 판단에서는 이쪽이 위험한 방향이다.

읽는 법:

- **Opus 4.8 과 Opus 5.5 는 맞힘이 1건 차이**(표본 105건에서는 구별되지 않는다). Opus 5.5 는
  낮게 부름이 2건 많고, 생각 토큰 때문에 건당 비용이 1.7배다. head 를 바꿀 까닭이 없다.
- **Sonnet 5.5 는 Sonnet 4.5 와 맞힘이 같지만 낮게 부름이 두 배**(18 대 9)다. draft 를 바꾸지 않는다.

  판정처럼 수렴하는 일에는 앙상블이 이득이 없다(Q-Atelier 가 수렴 작업에 consensus · single 을
  쓰는 판단과 같은 방향).
- Haiku 4.5 는 가장 약하지만 가장 싸고 빠르다. fast 를 바꾸면 Q-Atelier Q-Match 정확도 지표가
  그 모델에 묶여 있으므로 Q-Match 평가로 따로 잰 뒤에 정한다.

## 작성: 품질 문서 12과제 (무효)

현행(A)과 후보 넷을 두 심사 모델이 순서를 바꿔 가며 블라인드로 비교했다. 후보가 46~47승 1~2패로
나왔지만 믿지 않는다.

- 현행 초안 길이: 중앙 1,749자 · 최대 1,837자. **12건 중 8건이 낱말 중간에서 끊겼다**(후보는 12건 중 0~2건)
  (출력 한도 1,200토큰).
- 후보 초안 길이: 중앙 2,881자(B) ~ 4,659자(Opus 5.5 단독). 생각을 기본으로 하는 모델에
  생각 예산 8,000토큰을 더해 주는데(`headOutputBudget`), 생각에 다 쓰지 않으면 그만큼 본문이 길어진다.

다시 잴 때: 모든 구성의 «보이는 출력» 상한을 같게 맞추고, 끊긴 초안은 따로 센다.
운영의 앙상블 한도(1,200 · 1,600토큰)에서 실제 초안이 잘리는지도 함께 확인한다.

## 운영 한도 점검: Q-Atelier 작성 도우미

운영은 본문 한도 500 · 600 · 700토큰으로 부른다(내부 심사 · 510(k) 자체 문서화 · CAPA). 운영 구성(A)으로
같은 12과제를 불렀다.

| 한도 | 최종본 잘림 | 3사 초안 잘림 | 건당 비용 |
|---|---|---|---|
| 500 | 0/12 | 28/36 | $0.075 |
| 600 | 0/12 | 25/36 | $0.076 |
| 700 | 0/12 | 24/36 | $0.075 |

- 최종본은 잘리지 않는다(관리자가 생각 몫을 더 받는다).
- **3사 초안은 3분의 2 이상이 한도에서 잘린 채 관리자에게 간다.** 관리자는 잘린 초안을 모아 종합하고 있다.
  초안 한도를 넓히거나 단일 모델로 바꾸는 것을 검토한다(오너 결정).

### 초안 규칙 두 가지 비교 (한도 600 · 12과제)

예전 규칙(초안도 최종본 한도 그대로)으로 만든 최종본과 새 규칙의 최종본을 두 심사 모델
(GPT-6.1 Sol · Gemini 3.1 Pro)이 순서를 바꿔 가며 블라인드로 비교했다. 심사 비용까지 쟀다.

| 규칙 | 초안 잘림 | 건당 비용 | 중앙 시간 | 길이 중앙 | 예전 규칙과 비교 |
|---|---|---|---|---|---|
| 예전: 초안도 600 | 25/36 | $0.0755 | 40.7초 | 2,803자 | 기준 |
| 분량 안내 + 한도 1.5배 | 12/36 | $0.0690 | 40.3초 | 2,542자 | 18 대 30으로 짐 |
| 안내 없이 한도 3배 | 20/36 | $0.1018 | 62.0초 | 3,818자 | 23 대 15로 조금 이김 (Gemini 심사 10건 실패) |

- 분량 안내는 잘림을 절반으로 줄였지만 초안이 짧아져 관리자가 받는 재료가 줄고 품질이 떨어졌다.
- 한도 3배는 조금 이겼지만 비용 +35% · 시간 +50% 이고, 최종본이 36% 길어 긴 답 쏠림을 떼어 낼 수 없다.
  한도를 3배로 늘려도 초안의 절반 넘게가 여전히 잘렸다(초안이 본래 길다).
- **결론: 둘 다 기본으로 켜지 않는다.** 라이브러리는 두 규칙을 환경변수로만 켤 수 있게 두고 기본값은
  예전 동작이다. 비용: 생성 $2.05 + 심사 $1.12 = $3.17.
